- [x] **3.1 Judge.** `judge(sentence, citations, chunks)` returns a per-sentence verdict in strict JSON: `supported | partial | unsupported`, plus three flags: `quoteIsRule` (not a worked example, domain brief §Worksheets), `editionStated` (V slice), and a one-line reason. The quote and chunk text are wrapped as data, using the same escaping as `buildPrompt` (rule 4). The verdict is checked with zod, and a schema failure is logged as `schema_invalid`, never retried silently. The default model is `claude-opus-5-5` (D-19), with purpose `judge` and `assertBudget` before each call. *Acceptance:* unit tests on the schema and the prompt shape, plus an integration test with `fetch` stubbed and its `ModelCall` row.
- [ ] **3.2 Planted-fabrication fixtures.** `eval/fixtures/fabrication.json` holds ≥ 20 fixtures, ≥ 4 for each of the five types: changed number, changed year, inverted condition, invented exception, and right sentence on the wrong edition. Each fixture is built from a real verified answer (stored rows), with exactly one planted sentence and a `signature`. ≥ 5 clean controls are added. Fixtures are frozen once written (rule 11), and adding the set gets a decisions entry. A subagent drafts them from stored answers and Shane confirms (D-29).
- [ ] **3.3 Gate run.** `npm run eval:judge-gate` scores a catch only when the judge marks the planted sentence `unsupported` or `partial`. The target is ≥ 95% caught with 0 of N controls condemned. Below target, the judge prompt is revised, the gate is re-run, and every attempt is recorded (attempt, prompt hash, caught n/N). Results go to `eval/results/judge-gate-<snapshot>-<date>.json`.
- [ ] **3.4 Shane's grades (owner hand step).** 20 answered sentences sets, drawn from one full hybrid + Sonnet run (3.7), including the six answered hand-10 questions. They are written to `eval/grades.md` with one verdict per sentence, on the same three labels as the judge. The judge's verdicts are hidden from Shane while he grades.
- [ ] **3.5 Cohen's κ.** A pure function `cohenKappa(a, b, labels)` with unit tests: a textbook 2×2 case, perfect agreement = 1, chance-level agreement ≈ 0, and the degenerate case where both raters use one label. The κ of the Opus judge against Shane on the 3.4 sentences is reported with n, alongside raw agreement. The target is ≥ 0.7. Below that, the judge prompt is revised, 3.3 is re-run, and the scorecard says so.
- [ ] **3.6 Sonnet-judge κ check (D-19).** The same 20 answers go to `claude-sonnet-5-5`. If its κ against Shane is within 0.05 of Opus's, Sonnet becomes the routine judge for the matrix. Otherwise Opus stays and the matrix cost is re-estimated before 3.8.
- [ ] **3.7 Full-run harness.** `npm run eval:answers -- --retriever=… --model=… [--theta=off]` runs all 41 golden questions, each as its `callerRole`, under one run id. It refuses to start if the estimate for answers plus judge calls exceeds $3 (D-18). It stores an `Answer` row per question with its gate score, and judge rows per sentence. UNVERIFIED questions are skipped and counted (0 today).
- [ ] **3.8 Ablation matrix.** {fts, dense, hybrid} × {`claude-haiku-5-5`, `claude-sonnet-5-5`}, Haiku cells first (PRD risk table). **θ as an axis at no extra cost:** dense and hybrid cells run with the gate recorded but not enforced (`--theta=off`), so the θ values {off, 0.52, 0.559, 0.58} (D-29) are derived from the stored `denseTop` with zero calls. A question below θ′ counts as `NO_RELEVANT_PASSAGE`, and every other question keeps its stored answer. fts is ungated (D-17b). This is the only place θ may move, and a move is a decisions entry made on the full set, never on the hand-10 alone. Check `config/prices.json` has Haiku before the first call. Estimated cost (PRD): ≈ $4–7.
- [ ] **3.9 Scorecard.** `npm run eval:scorecard` reads only stored rows and makes zero model calls; a test asserts that `fetch` is never called. It prints the PRD metrics table with the measured number and n beside each target: citation verbatim, expected passage cited (A, M) per retriever, sentence support (A, M, V), refusal on U with false answers listed by id, answered-or-partial on A and M, tier leaks on P, edition labeled on V, fabrication caught, κ, injection n/N, and build spend. It also prints the retrieval table from 1.11 and the answered / partial / refused split (O-9). `JUDGE UNCALIBRATED` is shown on every judge column until 3.3 and 3.5 pass. It writes `eval/results/scorecard-<snapshot>-<date>.md`.

**Exit criteria:** `npm test`, typecheck, lint, `corpus:check` and `permissions:verify` are green. The fabrication gate and κ are measured and recorded, whether they pass or fail. The matrix has 6 cells stored. The scorecard regenerates with zero calls and no target lacks a number. Spend is printed, expected ≈ $5–10 of $25.
