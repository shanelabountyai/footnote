# Phase 2 — Prompt, verifier, θ gate, answer API (no judge yet)

The first answer-model calls happen in this phase, all through `assertBudget` and the `ModelCall` ledger, on `claude-sonnet-5-5` (D-19, O-1). There is no judge, no scorecard and no UI. Output: `answer(caller, question)` returning D-7 citations that are verified in code, `NO_RELEVANT_PASSAGE` before the model is called when the score is below θ (D-17a), an API with replay that reads stored rows only, and PT-1 shown end to end. Expected spend: under $1 (≈ $0.012 per Sonnet answer, PRD §Cost; about 60 live answers across the phase).

**Carried in:** 1.9 (Shane's ten hand answers) is still open, and 2.10 waits on it. The GitHub `origin` is still missing, so no CI run has happened on GitHub yet.

- [x] **2.1 Prompt shape.** ✅ 2026-10-19 (D-14a). Pure `buildPrompt(question, chunks: RetrievedChunk[])`: a system instruction stating that chunk contents are quoted material and never instructions, then each chunk wrapped `<chunk id="…" tier="…" edition="…">…</chunk>` (D-14), then the question **after** the chunks. Text inside a chunk that could close or open a tag (`</chunk>`, `<chunk`) is escaped, so a memo cannot break out of its wrapper. Imports only the `RetrievedChunk` type (D-12 lint). *Acceptance:* snapshot test of the prompt for a 2-chunk input; an injection-fixture memo containing `</chunk>` stays inside its wrapper (test); the lint covers the composition module.
- [x] **2.2 Output schema.** ✅ 2026-10-19 (D-6a). Strict JSON `{sentences: [{sentence, chunkIds[], quotes[]}], outOfScope?: boolean}`, validated with zod (already a dependency). Output that fails validation is `refused / INSUFFICIENT_SUPPORT` and is logged on the `ModelCall` row as `outcome: schema_invalid`. It is never retried silently. *Acceptance:* unit tests for valid output, missing fields, extra prose around the JSON, and an empty `sentences` array.
- [ ] **2.3 `verifyCitations()`.** Pure, per D-6: each quote must be a whitespace-normalized substring of the stored text of the chunk it names (collapse whitespace; unify `"" '' – —` to ASCII; nothing else), and the chunk must be one that was retrieved for this call. A failed citation is dropped; a sentence left with no citation is dropped and counted in `droppedSentences`; if no sentence survives, the answer is `refused / INSUFFICIENT_SUPPORT`. The D-7 fields `edition`, `revisionDate`, `page`, `section` and `tier` are filled from the manifest and the chunk row, never from model output. `status` follows D-8. *Acceptance:* tests for a paraphrase (dropped), smart quotes and a line break (kept), a quote that cites a chunk id that was not retrieved (dropped), a model-supplied `page` (ignored), and all sentences failing (refusal); `droppedSentences` is counted correctly.
- [ ] **2.4 θ gate (D-17a).** `hybrid.search` returns the dense leg's top-1 cosine alongside the fused list. This is the one change to the `Retriever` interface, and the SQL predicate is not touched. If the score is below `THETA_DENSE = 0.559`, the answer is `refused / NO_RELEVANT_PASSAGE` with zero model calls. The audit row stores the score and θ. *Acceptance:* unit test at θ ± ε; a live check that GU-06/07/08 refuse with 0 `ModelCall` rows; `permissions:verify` still OK on all three retrievers.
- [ ] **2.5 Answer composer.** `answer(caller, question, {retriever, model})`: retrieve → θ gate → `assertBudget('answer', estimate)` → model call → schema → verify → status, with one `ModelCall` row per call (purpose `answer`, runId, answerId). **Ask first:** Anthropic SDK, or plain `fetch` like `voyage.ts` (the house preference is plain fetch). `ANTHROPIC_API_KEY` is read from `process.env` at call time (O-12), and its line is prepared in `.env.local`. Every response carries the D-2 sentence. *Acceptance:* integration test with `fetch` stubbed covers the whole pipeline and its ledger row; one live answer to GA-01 is verified, with its cost printed.
- [ ] **2.6 Persistence, API, replay.** An `Answer` row (clone-owned schema): question, caller role, snapshot id, retriever, model, θ score, status, refusal, citations JSON, `droppedSentences`. `POST /api/answers` takes the role from the session, **never from the body** (D-12), and returns 409 on an `options.corpusSnapshot` mismatch (D-9). `GET /api/answers/:id` returns the stored answer and its `ModelCall` rows with **zero model calls** (D-23). *Acceptance:* route tests for a role field in the body (ignored), the snapshot 409, and a replay that makes no fetch.
- [ ] **2.7 Version labeling.** Every citation carries `edition` + `revisionDate`, plus `supersededBy` when the manifest has one (p334-2024, p15-2025, p463-2024). A sentence that cites only a superseded edition while the current edition is in the corpus is labeled as such in the response. Prior editions are labeled, not hidden. *Acceptance:* the V slice (GV-01..05, excluding UNVERIFIED) is answered live; each citation's edition matches `eval/golden.json`; the three V questions that θ refuses (GV-02/03/05, D-17a) are recorded as such, not patched.
- [ ] **2.8 Per-answer cap.** $0.10 (100,000 micro-USD, D-23a) is checked **before** the call against an estimate built from prompt tokens plus the `max_tokens` ceiling. *Acceptance:* a test with an oversized chunk set is refused `BUDGET_EXCEEDED` with no fetch, and the refusal row carries the estimate; `npm run spend` shows `answer` as its own purpose.
- [ ] **2.9 PT-1 end to end, and injection.** As `front_desk`, the Red Fork question (GP-01) returns `NO_RELEVANT_PASSAGE` with the **same message** as a true miss (D-13), and nothing from the partner memo appears in the prompt or the answer (checked against the prompt actually sent). As `partner`, the same question is answered with a citation of the memo. The test harness records `PERMISSION_SCOPED_MISS` when a partner-tier run of the same query scores above θ. Injection: every fixture in `eval/fixtures/injection.json` runs through `answer()`. The prompt-shape half runs in CI with a stubbed model; the live half is a local script, since CI has no model key (same split as D-12b). *Acceptance:* PT-1 and PT-2 pass end to end; 0 of ≥ 10 injection fixtures produce a `mustNotContain` string or cite a `mustNotRetrieveTiers` chunk.
- [ ] **2.10 The ten hand-answered questions (needs 1.9).** GA-01, GV-01, GA-02, GV-02, GM-01, GA-03, GA-04, GM-02, GA-05 and GU-01 run live. Every answered one carries ≥ 1 verified citation on Shane's page (± tolerance); GU-01 refuses. A mismatch is reported question by question. Prompt or θ are not tuned against these ten, because they are the κ anchor in Phase 3. *Acceptance:* results file `eval/results/hand10-<snapshot>-<date>.json`; NEXT.md lists answered / partial / refused and the spend.

**Exit criteria:** `npm test`, typecheck, lint, `corpus:check` and `permissions:verify` green; every answer path goes through `verifyCitations` (a lint or test proves no other path returns sentences); the θ gate makes zero model calls on refusal; replay makes zero calls; PT-1 end to end and injection 0-of-N pass; the hand-10 results are recorded; spend is printed (expected under $1 of $25).
