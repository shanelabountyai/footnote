- [ ] **4.1 Service API key (O-10).** `ApiKey` table: sha256 hash, label, role fixed to `service`, `revokedAt`. `POST /api/answers` accepts `Authorization: Bearer <key>` as an alternative to the session. The role comes from the key row, never the body (D-12). The key is shown once, by a script (`npm run apikey:create`), never logged. *Acceptance:* integration tests: a valid key answers with public-tier chunks only (the prompt holds no staff chunk); a revoked or unknown key returns 401 with no fetch; the body role is ignored. `permissions:verify` adds a `service` PT-1 case.
- [ ] **4.2 Audit view.** `/o/[org]/answers` is a list of stored answers (question, caller role, status, refusal code, snapshot, cost from ModelCall) and `/o/[org]/answers/[id]` shows the sentences with their citations (doc, edition, page, quote) and the superseded label. Partner-only. It is read-only and goes through the same GET check as `GET /api/answers/:id` (D-26). *Acceptance:* one Playwright spec per page; front_desk gets 404.
- [ ] **4.3 The one UI page.** An ask box for a signed-in staff user. It shows the answer with each sentence's citations inline, the refusal message on a refusal, the disclaimer on every answer, and the snapshot id. No chat history, no streaming. *Acceptance:* Playwright: one answered question (the model call stubbed at the fetch boundary, or a replayed stored answer), one θ refusal with no call, and the disclaimer present on both.
- [ ] **4.4 N9 contract doc.** `docs/n9-contract.md`: request and response JSON, the refusal codes and their meaning, the guarantee that every sentence carries a verified citation, the `service` scope (public tier only), the caps, and what a client must do with `partial`. It is checked against the zod schemas by one unit test that parses the doc's examples.
- [ ] **4.5 DEMO.md.** Screen by screen: the commands, the accounts and where each credential lives, which sample questions to ask (one answered, one superseded-edition label, one U refusal, one permission-scoped miss as front_desk), what to say at each stop, a troubleshooting table, and a *what to concede before you're asked* section (κ 0.17, the missed targets, synthetic private tier, not deployed). Every command is run once before it is committed.
- [ ] **4.6 Write-up.** Engineering write-up: what was measured, with the scorecard numbers beside every claim (rule 7), the retrieval comparison with no winner wording, *Defects Found* and *Hardest Bug* sections.
